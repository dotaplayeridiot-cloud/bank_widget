# Bank Widget

Учебный проект виджета банковских операций клиента. Маскирует реквизиты,
преобразует даты, фильтрует операции по статусу и сортирует их по дате.

## Установка

Требуются Python 3.15 и Poetry. Откройте папку проекта в PyCharm,
выберите интерпретатор Poetry и установите зависимости:

```bash
poetry install --with dev,lint
```

## Структура

- `src/masks.py` — маскировка карт и счетов.
- `src/widget.py` — маскировка строки с реквизитами и форматирование даты.
- `src/processing.py` — фильтрация и сортировка операций.
- `tests/` — проверки функций.

## Обработка операций

`filter_by_state(operations, state="EXECUTED")` возвращает новый список
операций с указанным статусом, сохраняя их исходный порядок.
Записи без `state` пропускаются; регистр статуса учитывается.

`sort_by_date(operations, is_reverse=True)` возвращает новый список,
отсортированный по ключу `date`: по умолчанию новые операции идут первыми.
Передайте `is_reverse=False` для сортировки от старых к новым.
Даты должны быть строками ISO 8601 в едином формате, например
`2019-07-03T18:35:29.512364`, как в условиях задания. Ключ `date` обязателен.
При одинаковых датах сохраняется исходный порядок записей.
Обе функции не меняют исходный список и словари; пустой ввод даёт пустой список.

```python
from src.processing import filter_by_state, sort_by_date

operations = [
    {"id": 1, "state": "EXECUTED", "date": "2019-07-03T18:35:29.512364"},
    {"id": 2, "state": "CANCELED", "date": "2018-09-12T21:27:25.241689"},
    {"id": 3, "state": "EXECUTED", "date": "2018-06-30T02:08:58.425572"},
]

executed = filter_by_state(operations)
print([item["id"] for item in executed])  # [1, 3]
print([item["id"] for item in filter_by_state(operations, "CANCELED")])  # [2]
print([item["id"] for item in sort_by_date(operations)])  # [1, 2, 3]
print([item["id"] for item in sort_by_date(operations, False)])  # [3, 2, 1]
```

## Генераторы (домашняя работа 11.1)

Модуль `src/generators.py` обрабатывает данные лениво, по одному элементу.

- `filter_by_currency(transactions, currency)` возвращает итератор транзакций
  с заданным кодом валюты (регистр учитывается), сохраняя исходный порядок.
- `transaction_descriptions(transactions)` выдаёт описания через `yield`, включая повторения.
- `card_number_generator(start, stop)` выдаёт номера от `start` до `stop` включительно:
  16 цифр с ведущими нулями, разделённые на четыре группы пробелами.
  Допустимые границы: 1–9999999999999999. Вне диапазона при переборе возникает
  `ValueError`; при `start > stop` результат пуст.

Пустой список транзакций даёт пустой итератор. Функции не меняют исходные данные.
Ожидается структура транзакций из задания: `operationAmount.currency.code`
и строковое поле `description`; отсутствие обязательного поля вызывает `KeyError`
при чтении соответствующего элемента.

```python
from src.generators import card_number_generator, filter_by_currency, transaction_descriptions

transactions = [
    {"operationAmount": {"currency": {"code": "USD"}}, "description": "Перевод организации"},
    {"operationAmount": {"currency": {"code": "RUB"}}, "description": "Перевод со счета на счет"},
]

usd = filter_by_currency(transactions, "USD")
print(next(usd)["description"])  # Перевод организации
print(list(transaction_descriptions(transactions)))
# ["Перевод организации", "Перевод со счета на счет"]
for number in card_number_generator(start=1, stop=2):
    print(number)
# 0000 0000 0000 0001
# 0000 0000 0000 0002
```

Тесты генераторов используют fixture и параметризацию: USD/RUB, отсутствие
совпадений, пустой ввод, повторения, ленивость, формат и границы номеров.
`poetry run pytest -q` запускает все тесты и обновляет HTML-отчёт
`coverage_html/index.html`. Настроен порог покрытия выше 80% (минимум 81%).

## Декоратор log (домашняя работа 11.2)

Модуль `src/decorators.py` содержит параметризованный декоратор `log`.
`@log()` пишет в консоль, `@log(filename="mylog.txt")` — в файл UTF-8
в режиме добавления. Файл создаётся автоматически, родительская папка
должна существовать; относительный путь считается от рабочей папки программы.

Для каждого вызова записываются начало и конец с локальным временем ISO 8601
и часовым поясом, имя функции и входные аргументы. При успехе выводятся
`имя ok` и результат, при ошибке — тип и текст исключения, `args` и `kwargs`.
После логирования исходное исключение передаётся дальше. Возвращаемый объект,
имя, docstring и аннотации функции сохраняются благодаря `functools.wraps`.

```python
from src.decorators import log

@log(filename="mylog.txt")
def my_function(x: int, y: int) -> int:
    """Сложить два числа."""
    return x + y

assert my_function(1, 2) == 3
```

Пример файла (время зависит от момента вызова):

```text
my_function start: 2026-11-27T01:00:00+03:00. Inputs: (1, 2), {}
my_function ok
my_function result: 3
my_function end: 2026-11-27T01:00:00+03:00
```

Пример консольного логирования ошибки:

```python
@log()
def divide(x: int, y: int) -> float:
    """Разделить два числа."""
    return x / y

try:
    divide(1, 0)
except ZeroDivisionError:
    pass  # Ошибка уже записана; вызывающий код решает, как её обработать.
```

Между записями `start` и `end` появится строка:
`divide error: ZeroDivisionError. Inputs: (1, 0), {}. Error: division by zero`.

Тесты в `tests/test_decorators.py` используют `capsys`, `tmp_path` и
параметризацию. Проверяются оба назначения логов, исключения, кириллица,
добавление в существующий файл, метаданные и сохранность возвращаемого объекта.
`poetry run pytest -q` запускает все тесты и обновляет отчёт
`coverage_html/index.html` с порогом покрытия 81%.
Работа сдаётся отдельным PR из `feature/homework_11_2` в `develop`.
